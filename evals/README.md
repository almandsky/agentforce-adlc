# ADLC Evals

Evaluation framework for Agentforce ADLC skills using LLM-as-judge pattern.

## Overview

This framework evaluates the quality of agents generated by `/adlc-author` using a
two-stage pipeline:

1. **Validator gate** — `sf agent validate` runs first. Syntax, required blocks,
   and deploy-readiness are ground-truth checked by the compiler. If validation
   fails, the test scores 0 and LLM judging is skipped.
2. **LLM as Judge** — Claude evaluates semantic quality: intent capture, FSM
   design, safety, conversational quality. Only runs on validator-passing agents.

- **Assertion labels** — semantic capabilities being tested (fsm, safety, actions, etc.)
- **Test tags** — vertical domains the test belongs to (customer-service, hr-agent, etc.)

## Quick Start

```bash
# Validate a suite (no execution)
python runner.py --suite suites/basic-authoring.json --validate-only

# Run suite with pre-generated agents
python runner.py --suite suites/basic-authoring.json --agent-dir ./agents/ --output results.json

# Generate report
python reporter.py results.json --format detailed
```

## Assertion Labels

Labels describe **what capability** is being tested:

| Category | Examples | Description |
|----------|----------|-------------|
| `structure:*` | `structure:linked-vars`, `structure:system-messages` | Semantic structure choices |
| `fsm:*` | `fsm:no-orphan-topics`, `fsm:verification-gate` | FSM architecture |
| `actions:*` | `actions:level1-definition`, `actions:slot-filling` | Action definitions |
| `logic:*` | `logic:post-action-top`, `logic:after-reasoning` | Control flow |
| `safety:*` | `safety:ai-disclosure`, `safety:no-impersonation` | Responsible AI |
| `chat:*` | `chat:welcome-message`, `chat:topic-routing` | Conversation quality |
| `instructions:*` | `instructions:procedural-mode`, `instructions:actionable` | Instruction quality |

**Not here:** syntax (tabs, booleans, nesting), required blocks, config fields,
deploy readiness. Those are enforced by the `sf agent validate` gate in
`runner.py` — if the compiler catches it, we don't LLM-judge it.

See `assertion_labels.py` for the complete list.

## Test Tags

Tags describe **what domain** the test is in:

| Category | Examples |
|----------|----------|
| Domain | `customer-service`, `hr-agent`, `healthcare`, `financial-services` |
| Pattern | `multi-topic`, `verification-gate`, `linear-flow` |
| Complexity | `minimal`, `easy`, `medium`, `hard` |
| Feature | `action-chaining`, `slot-filling`, `after-reasoning` |

See `test_tags.py` for the complete list.

## Suite Format

```json
{
  "name": "Suite Name",
  "surface": "agent",
  "tests": [
    {
      "id": "test-id",
      "prompt": "Description of agent to build",
      "tags": ["customer-service", "medium"],
      "assertions": [
        "[fsm:verification-gate] Verification required before sensitive actions",
        "[safety:ai-disclosure] Identifies as AI assistant"
      ],
      "negative_assertions": [
        "[safety:no-impersonation] Does NOT claim to be human"
      ],
      "expected_topics": ["verification", "orders"],
      "expected_actions": ["verify_customer", "get_order"]
    }
  ]
}
```

## Running Evaluations

### 1. Generate agents

First, generate agents for each test prompt using `/adlc-author`:

```bash
# For each test in the suite, run:
# /adlc-author <prompt>
# Save output to: agents/<test-id>.agent
```

### 2. Run evaluation

```bash
# Run against pre-generated agents (uses default SF org for validator gate)
python runner.py \
  --suite suites/basic-authoring.json \
  --agent-dir ./agents/ \
  --output results/run-001.json

# Specify org alias for validator gate
python runner.py \
  --suite suites/basic-authoring.json \
  --agent-dir ./agents/ \
  --org MyOrg

# Skip validator gate (offline / no SF CLI)
python runner.py \
  --suite suites/basic-authoring.json \
  --agent-dir ./agents/ \
  --skip-validator

# Run specific tests only
python runner.py \
  --suite suites/basic-authoring.json \
  --test-ids hello-world-faq order-service-agent \
  --agent-dir ./agents/
```

### 3. Generate reports

```bash
# Summary report
python reporter.py results/run-001.json

# Detailed report with per-assertion results
python reporter.py results/run-001.json --format detailed

# Failures only
python reporter.py results/run-001.json --format failures

# Markdown report
python reporter.py results/run-001.json --format markdown --output report.md
```

## LLM Judge

The judge uses Claude to evaluate assertions semantically (not just keyword matching).

Set your API key:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

If no API key is set, the framework falls back to basic heuristic evaluation (limited accuracy).

### Custom model

```bash
python runner.py --suite ... --model claude-sonnet-4-20250514
```

## Writing New Tests

### 1. Choose appropriate tags

- Pick a domain tag (`customer-service`, `hr-agent`, etc.)
- Pick a pattern tag if applicable (`verification-gate`, `multi-topic`)
- Pick a complexity tag (`easy`, `medium`, `hard`)

### 2. Write clear prompt

The prompt should describe what agent to build with enough detail for `/adlc-author`.

### 3. Write assertions

Use the `[label] description` format. Assertions should check **semantic quality
and intent capture** — not syntax. If `sf agent validate` would catch it, don't
write an assertion for it.

```json
"assertions": [
  "[fsm:verification-gate] Identity check required before account access",
  "[safety:ai-disclosure] System instructions identify the agent as AI",
  "[actions:slot-filling] Collects dates conversationally using ..."
]
```

### 4. Add negative assertions

For things that should NOT be present:

```json
"negative_assertions": [
  "[safety:no-impersonation] Does NOT claim to be a licensed professional"
]
```

## Interpreting Results

### Score breakdown

- **Overall score**: % of all assertions passed
- **By label**: Performance on each capability category
- **By tag**: Performance in each domain

### Common failure patterns

| Failure | Indicates... |
|-----------------|--------------|
| Validator gate fail | Agent Script syntax/structure broken — fix SKILL.md generation rules |
| Low `safety:*` | Responsible AI gaps — skill not proactively adding guardrails |
| Low `fsm:*` | FSM design issues — wrong pattern for use case |
| Low `actions:*` | Action definition problems — intent not captured correctly |

## Integration with CI

```bash
# Run eval suite and fail if score < 80%
python runner.py --suite suites/basic-authoring.json --agent-dir ./agents/ --output results.json
python -c "import json; r=json.load(open('results.json')); exit(0 if r['overall_score'] >= 0.8 else 1)"
```
